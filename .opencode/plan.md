## Loop protocol

For each queue item:
1. Read the relevant code (never guess an API).
2. Write the module + tests; run them; fix until green.
3. `--apply`, `--check` = `OVERLAY_OK`.
4. Commit with a real message, then `log-change --sha`.
5. Rebuild + recreate; verify in the live container with a read-only probe
   (`docker cp` a probe to /tmp, run `node /tmp/x.cjs`, never write to the store).
6. Append the result (PASS/FAIL + exact evidence) to `.opencode/state.md`.
7. Next item. Stop when the queue is empty or a hard blocker needs the owner.

## Decision policy (owner, 2026-10-27)

A human decision NEVER blocks the loop. It pauses only that one implementation
step, and only when neither the documents/designs nor a recommended default can
answer it. Otherwise decide, implement the recommended option, state the
assumption in the commit message and in `.opencode/state.md`, and continue.

Defaults already approved by the owner, use them without asking:
- structures: real faction structures via the factory, Citadel/EC/Refinery types
  that exist in `structureTypes`; pick the cheapest valid hull type if several fit.
- world spawn counts to create a real front: allowed (real NPCs, real factions),
  but the war itself must still be won by real weapons, never scripted.
- flags: enable what is needed in `compose.coop-probe.yaml`, re-check the file
  before each recreate because another session may regenerate it.

## Stop conditions (report, do not force)

- A step truly cannot be decided from documents/designs and has no recommended
  default: pause THAT step only, mark it `NEEDS_OWNER` in `.opencode/state.md`,
  and continue with the next queue item.
- Needs the EVE client to verify something visual: record `BLOCKED_CLIENT_CHECK`,
  keep the server-side proof, continue.
- Another session's container recreate or a shared-file conflict: wait, retry once,
  then continue with a non-conflicting item.
- Context limit: do NOT stop for context. Keep `.opencode/state.md` current after
  every item (done / next / exact file+line) so a compaction loses nothing, let the
  session compact, then continue from the handoff. Only stop when a queue item is
  genuinely blocked or the queue is empty.
