## 2. Deployed but NOT exercised

- `EVEJS_COOP_NPC_REFINERY=0` → no `living-npc-refined`, no `living-corp-treasury-swept`;
- `EVEJS_COOP_DISTRIBUTION_RUN` is commented out ("must be a deliberate operating choice, not a

Consequence: after this deploy the merged sale/receipt/treasury path has **not moved money on the
live world**. That was already true before the merge — the owner has no sell orders.

## 4. Event-loop lag (pre-existing, measured on the new image)

30 `coop-event-loop-lag` samples, median **1 293 ms**, max **3 196 ms**; RSS up to 4.36 GB with
`heapUsed` peaking at 3 967 MB against the 4 288 MB V8 limit (92.5 %).

- one freeze **per** `living-world-phase-cycle` (10 cycles / 10 lag events in the current run);
- the instrumented phases only explain ~380 ms of it (`native-faction-war-opening` worst 687 ms,
  `npc-reconcile` ~130 ms ×2, `universe-sites` ~35 ms) — 21 phase names are still unclassified;
- telemetry writes are **not** the cause (one cached fd, ~1.2 `writeSync`/s on ext4).

The tick is deliberately synchronous (`LIVING_WORLD_ASYNC_CYCLE_FORBIDDEN`), so the fix must remove
work per cycle or bound the expensive phases — not "await between phases".

## 6. The loop actually traded (2026-11-05 12:2x–13:0xZ)

The distribution switch was turned on deliberately (see `compose.coop-probe.yaml`), and two
blockers were found and fixed while watching it:

1. **The crossing ticker is the other half of the switch.** With `EVEJS_COOP_DISTRIBUTION_RUN=1`
   and `EVEJS_COOP_DISTRIBUTION` off, hull `980000093319` re-planned the same home crossing every
   56 s for six beats and never moved (`RETURN_CROSSING_PLANNED`). Enabled; the hull then flew the
   gate for real: `FOLLOW_GATE` with the gap falling 16 110 → 2 940 m, `SAME_NATIVE_SHIP_ARRIVED`
   from 30000142 to 30000145.
2. **The per-beat sale budget was a verdict instead of a bound.** After selling 12 times the run
   went `BLOCKED / SALE_STOPPED:CALL_LIMIT` with cargo still aboard, and a blocked run waits
   `BLOCKED_RETRY_MS` (30 min). It now continues in `SELL` with a fresh budget when the beat
   actually sold something; a beat that only collected refusals still ends `BLOCKED` after exactly
   `MAX_SELL_CALLS` real calls (pinned by `tests/coop-distribution-run.test.mjs`).
