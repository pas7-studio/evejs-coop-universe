# P0 Native Escort Escrow — proof-gated atomic refund

Draft safety infrastructure only, default OFF. This branch extends the native wallet provider, not the trusted NPC failure producer or live player-facing contract engine. It may NOT be deployed as full refund gameplay without additional verified native failure evidence.

## How it works

- Existing PR #69 source (already present on main) reserves real NPC corporation cash division in GameStore SQLite and settles exactly two player balances with a single transaction.
- New refundAtomic(contract) is a terminal alternative to settleAtomic. It refuses to run unless EVEJS_COOP_ESCORT_REFUNDS=1 AND its creator was injected with a server-side verifyNativeFailure callback.
- verifyNativeFailure must return durable, irreversible, authoritative proof of an actual native hauler wreck or an explicitly canceled route that had never issued warp; mere timeouts, missing ship objects, lost ACK, or user-requested strings are not valid evidence.
- The witness must exactly match the immutable contract, manifest, NPC corporation, failureWitnessID, nativeDurable, deliveryImpossible and noPriorPayout.
- Under the SAME existing GameStore atomic transaction, refundAtomic reads the original RESERVED escrow, adds exactly the previously deducted ISK back to the native corporate wallet and journal, and marks that escrow REFUNDED with failure witness ID. Any SQL failure rolls all of this back.
- Existing settleAtomic insists on RESERVED and therefore cannot pay a REFUNDED contract; refundAtomic also insists on RESERVED and cannot refund a SETTLED one. A repeat refund is rejected.
- verifyRefund reads the durable authoritative escrow row and exact original contract. It is safe after server restart; it NEVER recredits money.
- No separate synthetic wallet, faucet, compensation mint, client RPC or autogenerated refund after timeout.

## Remaining safety gates

1. Add actual failure producer to Stage C's durable flight journal: terminal physical wreck with authoritative native wreck/itemStore record, or server-attested prewarp cancellation that independently proves no warp was issued. It must survive restart and tie to immutable manifest.
2. Provide a trusted verifyNativeFailure closure on native server creation, not via client parameters. It must not rely solely on absence of a ship or on transient in-memory state.
3. Extend Stage A / Stage C contract journal with REFUND_PREPARED and REFUNDED, with fsync and reconciliation on uncertain COMMIT or callback, preserving the same trip claim and preventing a later payout.
4. Reconcile PR #53 actual cargo / wreck and PR #77 physical trip; do NOT refund once cargo delivered or payout prepared. Test no late transition from irreversible failure to delivered.
5. Real better-sqlite3 GameStore worker, two EVE clients, both wallets, corporate money, lost ACK, repeated requests and Docker crash/restart on disposable approved backup data before releasing flags.
