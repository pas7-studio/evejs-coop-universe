## Updated hypothesis

The baseline already contains **per-connection ClientSession** and a **multi-session registry**, so a complete rewrite of multiplayer session storage is probably unnecessary. However **two simultaneous game clients are not proven**. Highest-value next experiment: mock sessions through the existing registry and disconnect hooks, then scene observer notifications. Only after passing those tests assess protocol-specific transport.

## Concrete review/test checklist

1. Check duplicate account/character policies across handshake -> character binding -> chat/session registry.
2. Examine TCP socket close and error cleanup for idempotence, plus async dispatcher handling after socket closure.
3. Inspect shared `scene.sessions` and scene visibility/broadcast implementation for updates delivered to two distinct clients.
4. Test A disconnection does not remove B or unregister shared NPC materializations.
5. Capture auth/endpoint/TLS/XMPP expectations without changing client code or opening host ports.
6. Keep a per-feature PASS/FAIL matrix. No claims of working two-PC gameplay before permitted real tests.
