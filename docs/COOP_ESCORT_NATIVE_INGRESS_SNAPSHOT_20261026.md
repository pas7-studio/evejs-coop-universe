## Verified original pinned EveJS gap

The pinned upstream `gameboys84/EveJS@c3ea396b6761a0ed3e71ad5b8dd7507f9ae6d69f` saves native NPC `position`, `velocity`, `targetPoint` and `mode` through `nativeNpcStore`; `buildNativeRuntimeShipSpec` and `materializeNativeRuntimeEntity` do **not** persist or rehydrate `sessionlessWarpIngress`. ## Minimal opt-in implementation

- `integration/coopEscortNativeIngressSnapshot.cjs`: after the **genuine** native `warpToPoint` command succeeded and the original server-side `WARP_ACK_CONFIRMED` was durably appended, snapshot the NPC's **real** `sessionlessWarpIngress` once into `<nativeWarehouseRoot>/escort-native-ingress-snapshot/<manifestKey>.json`. Immutable exclusive-create (`wx`), file+directory `fsync`, original protected fleet/corporation/hauler/contract/cargo identity and exact predeparture source position. Does not serialize arbitrary client coordinates or mark an unconfirmed warp as true. Zero wallet calls in snapshot code. Invalid paths, link replacements, corrupt documents, short/expired/excessive duration and uncertain fsync ACK fail closed. Replay only permits byte-identical immutable original.
- `integration/coopNativeStationArrival.cjs`: requires `EVEJS_COOP_ESCORT_NATIVE_INGRESS_SNAPSHOT=1`, `EVEJS_COOP_ESCORT_NATIVE_WARP_RECOVERY=1` and all existing strict paid Stage I motion gates before creating the original cargo manifest or reserving corporate money. Snapshot is attempted only after confirmed native ACK and never before; a lost snapshot fsync ACK cannot authorize a reconstructed ingress. The original NPC can still physically continue its already-started warp, but snapshot status is explicitly recorded for operator QA, not treated as permission to pay.
- `scripts/coop-escort-ingress-materialize-patch.cjs`: exact pinned, byte-reversible hook on **new real stock native NPC materialization** in `nativeNpcService.js`, placed after native controller registration and ambient state initialization. Only when explicitly opted in, it calls the server-owned `coopNativeStationArrival.restoreNativeIngress`. Errors never abort native materialization. Never patches player ship construction or native warp solver.
- `restoreNativeIngress` refuses existing live ingress or an in-progress entity, and checks current original native source cargo + WARP_ACK + FUNDED + currently **RESERVED** native corporation escrow, original signed source two pilots, exact materialized NPC identity, immutable original snapshot (re-fsync + reread), original canonical station target offset and ship origin. The loaded native entity and original persisted position must both be within 1m of original source. Current native server time must be **before** the originally recorded travel-complete time (not extended on restart). Only then it restores the original `sessionlessWarpIngress` and `mode="WARP"`; it **does not call** `warpToPoint`, `fundBeforeWarp`, `manifest.prepare` or any native wallet/cargo mutation. Subsequent actual native movement observations still require valid original two-player midroute evidence.
- `scripts/patch-evejs-coop.cjs` registers both the new protected module and pinned `nativeNpcService.js` reversible transformer; no operator has to replace the source checkout by hand.

**Important limitation:** the original native materialization may broadcast an NPC before the opt-in restore hook runs; visual continuity, client lag, stock scheduler/wake and controller behavior remain unverified by actual EVE clients. The original warp is 6–30 seconds long. A normal container restart that lasts longer than the remaining ingress **cannot** restore it safely: do NOT rewind clocks, extend deadlines or generate fake checkpoints. A persistent player route is *not automatically an entitled paid contract* after downtime. Such a trip requires explicit independently proven refund/settlement or operator repair.

## Feature flags and rollback

`EVEJS_COOP_ESCORT_NATIVE_INGRESS_SNAPSHOT=1` is **OFF** unless explicitly enabled on a disposable GameStore clone. Requires `EVEJS_COOP_ESCORT_NATIVE_WARP_RECOVERY=1` plus all prior Stage I native motion/route witness, two-player predeparture, real corporate escrow, native manifest and warp-fence flags. Disabling it immediately restores old fail-closed behavior. Neither the physical NPC `main` server nor the live `evejs-data` volume was modified by creating this branch.
